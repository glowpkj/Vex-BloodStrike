--------------------------------------------------------------------------------

  O SINTOMA, dito com números:

      [pool] 3 candidates kept
      [live] fps 59  tracked 1  within 200m 0  on-screen 0  nearest -1.0m

  `tracked 1` e `within 200m 0` -- o único actor tem distância inválida.
  O `[body]` desta build nunca chegou a imprimir.

  O QUE JÁ ESTÁ DESCARTADO (não gastes tempo aqui):

    * NÃO são os ossos. Estão provados: a linha [body] de uma corrida anterior
      imprimiu  pos-root 0.116  head-pos 2.158  head.y 2.424  root.y 0.150.
      Esses são exactamente os valores que a secção 0.3 do ANALISIS fixou como
      prova (raiz a 12 cm dos pés, cabeça a 2,16 m). Os offsets
      off::BoneRoot=0x208 / off::BoneHead=0x214 estão CERTOS.

    * NÃO é o filtro de esqueleto. Ele deixa passar o actor real -- está a
      funcionar como desenhado.

    * NÃO é o pool que não cresce. Isso ERA o problema e está CORRIGIDO nesta
      sessão (sweep de fundo + merge, ver secção 0.6 do ANALISIS).

  DUAS HIPÓTESES, e são distinguíveis com uma corrida:

    HIPÓTESE 1 -- O build_pool inicial corre cedo demais.
      A varredura corre no instante de `[match] entered a match`, quando a
      cadeia do `local_` pode ainda não ter estabilizado. Noutras corridas o
      local_ leu (0,0,0) exactamente nesse instante. Se o pool nasce a partir
      de uma leitura má, nasce mal.

    HIPÓTESE 2 -- A assinatura +0x3E0 == 2 já não é a certa.
      Os números incomodam: 104958 passam o teste de 9,3 milhões (1,1%), e
      desses só 1023 têm posição legível (0,0097%). Isso é ruído, não uma

--------------------------------------------------------------------------------
  ARMADILHAS CONHECIDAS -- não voltes a cair nestas
--------------------------------------------------------------------------------

  * WS_EX_NOREDIRECTIONBITMAP é incompatível com este present path -- trava o
    primeiro Present. O caminho é LAYERED_CPU (--ulw).
  * A matriz da câmara é COLUMN-major com sign -1. É CONSTANTE MEDIDA
    (kForwardSign/kColMajor). Não voltes a votar isto.
  * SetWindowPos(HWND_TOPMOST) por frame perturba o raw input.
  * ShowWindow é um evento de activação -- usa só na transição, não por frame.
  * AttachThreadInput quebrou os botões do menu.
  * `taskkill` sem elevação dá "Acesso negado" no bs_esp.
  * O estande de tiro tem bots PARADOS -- dados de lá não valem para movimento.
  * O bone_find precisa que ANDES em linha recta. Jogador parado dá sinal fraco
    e o veredicto dele diz isso explicitamente.
  * O launch.ps1 foi reordenado mas NUNCA foi revalidado. O caminho directo
    (cmd elevado -> .\bs_esp.exe --ulw) funciona sempre.
